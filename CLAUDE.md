# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AHRA: a Godot 4.7 GDScript prototype of isometric 3D platformer mechanics (Jolt physics, physics interpolation on, D3D12 on Windows). Main scene: `res://demo/demo.tscn`. No build or lint step; the editor is `C:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe` (older 4.5/4.6 exes sit next to it, don't use them).

## Verifying changes (headless)

Tests are `SceneTree` scripts in `tests/`. One script = one suite; there is no per-case filter, except that the enemy, NPC and switch suites take section names after `--` (`-- pursuit swing_fly`, `-- key leave`, `-- plate carry`). Exit code = number of failed checks; the last line prints `SMOKE|PLATFORMS|PUZZLES|ENEMIES|NPCS|SWITCHES|SHAPE EDITOR|PLATFORM TOOLS|NPC TOOLS: OK` or `N FAILED`.

```sh
GODOT="/c/Program Files/Godot/Godot_v4.7.2-stable_win64_console.exe"
NOISE="git_plugin|git-plugin|GDExtension|copying library|FileAccess::exists"   # godot-git-plugin log spam

timeout 150 "$GODOT" --headless --path . -s res://tests/smoke_test.gd    2>&1 | grep -viE "$NOISE"   # player controller, ~45 s
timeout 150 "$GODOT" --headless --path . -s res://tests/platform_test.gd 2>&1 | grep -viE "$NOISE"   # moving platforms (demo/platforms)
timeout 300 "$GODOT" --headless --path . -s res://tests/puzzle_test.gd   2>&1 | grep -viE "$NOISE"   # walkthrough of all 10 puzzles, ~3 min
timeout 300 "$GODOT" --headless --path . -s res://tests/enemy_test.gd    2>&1 | grep -viE "$NOISE"   # enemies + player attacks, ~2.5 min
timeout 300 "$GODOT" --headless --path . -s res://tests/npc_test.gd      2>&1 | grep -viE "$NOISE"   # NPCs, story flags, fade, interactable pick, demo walkthrough, ~1.5 min
timeout 400 "$GODOT" --headless --path . -s res://tests/switch_test.gd   2>&1 | grep -viE "$NOISE"   # plates, doors, energy, weights, carry, dispensers, gravity zones on everything, memory, ~2 min
timeout 150 "$GODOT" --headless --path . -e res://tests/shape_editor_test.tscn -- --shape-editor-test 2>&1 | grep -viE "$NOISE"       # Shape Tools plugin
timeout 150 "$GODOT" --headless --path . -e res://tests/platform_tools_test.tscn -- --platform-tools-test 2>&1 | grep -viE "$NOISE"   # Platform Tools plugin
timeout 150 "$GODOT" --headless --path . -e res://tests/npc_tools_test.tscn -- --npc-tools-test 2>&1 | grep -viE "$NOISE"             # NPC Tools plugin
# editor tests need the editor, so they open a scene instead of -s; they share tests/editor_test.gd

timeout 150 "$GODOT" --headless --path . --quit-after 300 res://demo/demo.tscn   # load/run a scene, watch for errors
timeout 150 "$GODOT" --headless --path . --editor --quit-after 400             # catch errors in @tool scripts
```

Run the suites that cover what you touched after any player/world change. They check physics and logic only; game feel is untested, so say so.

Gotchas:
- A script error stops the test before `quit()` and Godot hangs forever: always wrap in `timeout`.
- `-s` scripts compile their statically typed dependencies before autoloads exist. In test scripts don't static-type classes that reference the `World` autoload (`PlatformProgram`, `PlatformTrackInstance`, `PlatformTrackGroup`, `PlatformSwitch`, `Npc`, `NpcTalk`, `WeightPlate`, `EnergySwitch`, `Door`, `Dispenser`, `GameArea`, `Channels`); use `Node3D`, `load()` their scripts and scenes at runtime, and fetch World via `root.get_node("World")`. For the same reason `Player`, `Enemy`, `Zone`, `Projectile` and `WeightBody` reach those classes only by group or `has_method`.
- CSG collision is a hollow trimesh and Jolt ignores back faces: a shape query whose shape sits entirely inside a CSG wall finds nothing. Cast a ray from outside too (as `Player.put_down` does).
- A fresh worktree has no `.godot` import cache: run the editor once (`--editor --quit-after 400`) before `-s` tests, or global classes like `Player` aren't found.
- Tests drive the game with `Input.action_press/release` and wait in physics frames. For timing-sensitive moves (swing release, jump/dash), probe a grid of frame timings rather than guessing.
- Skipping `World.time` while the player stands on a platform teleports the platform and flings the player (Jolt applies the jump as platform motion): place the player elsewhere first.

## Architecture

**`World` autoload (`world/world.gd`)**: state that survives scene changes (`time`, `channels`, `signals`). `World.time` is the world clock (advances in `_physics_process`, so it pauses with the tree). `World.channels` holds per-channel platform state changed by switches, keyed by scoped channel keys (`world/channels.gd`, `Channels`). A plain name like `lift` belongs to its area and is stored as `area:lift`; the area is the `GameArea.area_id`, which defaults to the scene file name. A `PlatformTrackGroup` with `channel_scope` on adds its name (`area:Group/lift`), so a set piece placed twice keeps separate states. A name with a colon is already a key: `platforms_a:remote` crosses areas, and `world:` is for game-wide states. Every `channel` and `end_signal` goes through `Channels.key(node, name)`. `World.flags` holds game-wide story flags (`flag`/`set_flag`, `flags_changed`), `World.npcs` NPC memory per placement (`npc_memory(Channels.id(npc))`), and `World.fade()` tweens a black overlay that survives scene changes. `World.switches` holds door switch state and `World.bodies` weight memory (see Switch puzzles). Saving the game is meant to be saving `time` + `channels` + `signals` + `flags` + `npcs` + `switches` + `bodies` (plain data) plus `Player.progression`. `World.spawn` names the marker the next area places the player at.

**Player (`player/player.gd`)**: a `CharacterBody3D` with a state machine of `RefCounted` `PlayerState` objects, one script per state in `player/states/`, preloaded into `Player.states`. `physics(delta)` returns the next state's name or `&""`. States hold a back-reference `p` and call shared helpers on the player (`ground_step`, `move_air`, `apply_gravity`, `landed_state`, `recover_state`...). Adding a state = new script + entry in `states`.
- Gravity can point anywhere (`set_gravity_dir`; walls and ceilings are walkable). Motion is split into vertical (along `up_direction`) and planar. Use `vspeed()`, `set_vspeed()`, `planar()`; never `velocity.y` or `Vector3.UP`.
- Stats: the `@export`s on Player are base values; gameplay reads them through `mult(stat)` = `1 + progression% + environment%` (additive). The percentages live in `StatMods` resources (`player/stat_mods.gd`); a new stat is a new `@export var` there, and `StatMods.names()` picks it up by reflection.
- Animation is a placeholder: states set `p.anim` and `_animate()` squashes/tilts the capsule. Meant to be replaced by an AnimationTree keyed on `anim`.

**Environment**: `EnvProfile` (`world/env_profile.gd`) is a resource with stat mods plus world physics (gravity mult, drag, wind, water, temperature). `EnvZone`s push and pop profiles on the player; overlapping zones are blended by `EnvProfile.combine` on top of `Player.ambient`.

**Shapes (`world/shape_set.gd`, `ShapeSet`)**: zones and moving platforms take their shape from their `CollisionShape3D` children (any shape type, several allowed). `ShapeSet` holds the shared logic as static helpers: drawing each shape (an internal `ShapeMesh` child: see-through debug mesh for zones, lit solid mesh for platforms), `bounds()`, editor redraw polling (`setup`/`refresh`), giving Ctrl+D copies their own shape resources, and the inspector rows (proxy properties `shapes/<child>/<property>` returned from the node's `_get_property_list/_get/_set`). The Shape Tools editor plugin (`addons/shape_tools`, enabled in `project.godot`) draws the Shapes section (Add Shape menu, Remove buttons, both undoable) and resize handles for every shape while the node is selected.

**Zones (`world/zone.gd`)**: `@tool` `Area3D` base, shaped through `ShapeSet` and drawn in its translucent `color`. Code that needs a size reads `bounds()` (AABB of all shapes); zones built in code get shapes via `add_shape()`. Every trigger (EnvZone, GravityZone, KillZone, Checkpoint, Teleporter, SceneDoor, CutsceneTrigger, WeightPlate, Interactable → PlatformSwitch, NpcTalk) extends it and overrides `_player_entered` / `_player_exited` (and `_enemy_*`, `_npc_*`, `_weight_*` where those are affected: `GravityZone` flips all four, `KillZone` destroys weights). The player keeps every `Interactable` it stands in (`Player.interactables`) and interact reaches the nearest one whose `can_interact()` is true (`Player.interactable`, picked each physics frame). Because these are `@tool`, their code runs in the editor; guard runtime-only logic with `Engine.is_editor_hint()`.

**Moving platforms**: positions are a pure function of time, never stepped incrementally, so platforms are in place when an area loads and stay in sync across areas. Roles:
- `PlatformTrackInstance` (`world/platform_track_instance.gd`), a track: one or more Path3D children (multipath), a `sequences` array, and its `MovingPlatform` child.
- `PlatformSequence` (`world/platform_sequence.gd`, a Resource): moves the platform between two anchors of one of the track's paths (`path` index, a dropdown of the path names). It has trips (0 = forever), one way or round trip (one-way trips alternate direction), speed, a start wait (before each departure) and an end wait (on each arrival). Each sequence starts where the previous one left the platform: the track keeps `start_anchor` in step and read-only. On another path, the start is that path's anchor nearest the platform: a junction, with a warning if it is more than `JOIN` (0.05 m) away. On a closed path, start = end is a full lap.
- End signals: a sequence's `end_signal` names a channel. Each time the sequence ends (after its end wait), `World.power_on` starts the tracks waiting on that channel, so one signal can wake several tracks. `_send_signals` counts ends in `World.signals`, so a reload neither misses nor repeats one, and back-dates each from the unclamped channel drive, so a clock skip or an unloaded area still starts the targets at the right time. In the editor, `woken_at()` gives the same timing to the preview clock. Demo: the Relay bay in platforms_a.
- `PlatformTrackGroup` (`world/platform_track_group.gd`): organises tracks. With `circuit` on, its tracks share the group's `MovingPlatform`, which plays each track's sequences in child order.
- `PlatformProgram` (`world/platform_program.gd`), the base of track and group: the program math (`_compile` → `_plan`, `_fold`, `point_at`) and the timing settings: `after_last` (stop / start over / play backwards), `offset`, `platforms` (evenly spaced internal copies), `channel`, `starts_on`, `preview`, `show_track`. A track inside a circuit hides them (`plays()` is false).
- `MovingPlatform` (`world/moving_platform.gd`): only the body: shapes through `ShapeSet` (a `surface` EnvZone wraps each one, grown 0.3 m), colour, and collision kept off for the first physics frames while Jolt moves it from the scene origin to its place.

The clock is `World.drive(channel, starts_on)`. `PlatformSwitch` actions (POWER, RUN, REVERSE, SPEED, START_WAIT, END_WAIT) only mutate `World.channels` through `World.toggle/run/reverse/set_rates`; programs re-derive positions from that, and rate changes are rebased per platform (`_shifts`) to keep motion continuous.

**Platform Tools (`addons/platform_tools`)**: one icon menu in the 3D toolbar ("Platform Track builder": Shape Refs, Tracks with New Track first, Preview Settings), plus a second icon menu while tracks are selected (Play in Editor, Group, Switch, Reconnect). These act on the track, or on its circuit for circuit tracks. Shape Refs adds a `ShapeReference` (`world/shape_reference.gd`, an editor-only guide that frees itself in game; `cast()` hits any shape via its debug mesh's `TriangleMesh`). Plane references are `WorldBoundaryShape3D` (infinite; cast analytically). New Track takes viewport clicks (`_forward_3d_gui_input`, forwarding always on) as anchors, snapped onto references or on a plane through the last anchor, previewed in 3D by `addons/platform_tools/track_preview.gd` (an internal child of the edited scene while placing; its look is editor settings under `platform_tools/preview/`, edited from Preview Settings), and builds a track with a box platform doing round trips forever. The track draws a ghost of the platform at its path end, and config warnings enforce the structure. Clicking the first anchor again (3+ placed) closes the loop: a full lap forever. Inside a circuit, a new track runs once and is joined to its neighbours. Add Path (selected-track menu) draws another path into the track. Its anchors snap onto the track's own anchors (junctions), and a one-way run along the new path is added when the program ends where the path starts. The Shape Refs (N) / Tracks (N) submenus list, select and remove those nodes (removal restores owners on undo). Play in Editor sets `preview` on the selected tracks' programs. Switch adds a `PlatformSwitch` to the selected track and puts the programs on its channel. Channels come from `addons/platform_tools/channel_registry.gd`: the keys of every saved `.tscn` (`keys_in` resolves each node's `channel` and its sequences' `end_signal` in its scope) plus the open scene's nodes. The picker lists only this scope's channels, by plain name, plus the current value when it links another area. Typing a plain name makes a new channel, refused if this scope already uses it. Typing `area:name` links another area's channel, and the note says where that channel is used. Picks are stored with `Channels.relative`, so plain names stay plain and a cross-area pick stays a full key; the inspector's `channel` field on tracks, circuits and switches uses the same picker (`channel_picker.gd`, `channel_property.gd`). Saving a scene (or any filesystem change) re-bakes the door switch registry (`world/switch_registry.tres`, `ChannelRegistry.bake`). Group moves selected tracks into a `PlatformTrackGroup`; its `show_paths` / `show_destination` are read by its tracks each editor frame. The group's inspector `circuit` checkbox calls `set_circuit`: the first track's platform moves under the group, the others go, each track gets a single run from its first anchor to its last, and neighbouring ends meet halfway (`join_circuit`, also last → first when the circuit starts over). Turning it off gives each track a copy of the platform. Reconnect re-joins the ends. Snap to Grid (step in Preview Settings) snaps new anchors, then drops them back onto their reference surface or plane. While the mouse button is down on a selected track path, `_on_drag_changed` lands each anchor the Path3D editor moves or adds onto the reference under it, seen from the camera, and onto the grid. Godot's own undo step records the result. Tracks → Preview All Platforms sets the static `PlatformProgram.editor_clock`, which every program shows in the editor in place of its own preview, as if switched on at 0. A toolbar slider (manual) or the plugin's `_process` (automatic) drives it. All undoable.

**Enemies (`enemy/`, guide in `docs/enemies.md`)**: `Enemy` (`enemy/enemy.gd`) is a `CharacterBody3D` built like Player: one `EnemyState` script per state in `enemy/states/` (idle, pursuit, attack, hurt, stun, flee, death, puppet, plus the moves jump, dash, climb, swim, swing; flying is a mode of the chase, `fly_toward`). Chasing is reactive: `step_toward` reads `probe(dir)` (open / wall / gap / water, rays skip the player and enemies, ignore back faces because CSG collision is a hollow trimesh) and walks, hands off to a move (which returns to `goal`), or gives up for `give_up_time`. Enemies never walk off ledges or into water on their own; only `hurt` (no ledge check) or a stun in the air puts them there. `abilities` flags pick 1-2 moves; jumps are solved arcs (`solve_jump`/`arc_to`, plain gravity, planar speed re-applied in flight). Stats are exports (health, armor fraction, weight: knockback = push / weight, stamina: 0 = stun, oxygen, mood: flees under `flee_mood`). Everything hurts an enemy through `hit(damage, push, from)`. Types are inherited scenes of `enemy/enemy.tscn`; a type script replaces states in `_init()` (`enemy/burrower/`); `enemy/runner/runner.tscn` is exports only. Presentation reads `anim`, the `cue(name)` signal and `died(cause)`; `_animate()` is a placeholder. Zones reach enemies through `Zone._enemy_entered/_enemy_exited` (EnvZone, KillZone only). The player's placeholder combat: `melee` state (`Player.melee_hit`) and `shoot` (`world/projectile.gd`, aim assist); input actions `attack`/`shoot`. Demo: `demo/enemies/enemies.tscn`. `Enemy` must not reference the `World` autoload (`-s` tests compile it first).

**NPCs (`npc/`, guide in `docs/npcs.md`)**: `Npc` (`npc/npc.gd`) is a `CharacterBody3D` with no state machine: idle (the head follows the player within `notice_distance`) or running one `NpcInteraction` as an `await` coroutine (`play`). Its `interactions` list is priority order: a trigger (KEY: interact in its `Talk` zone, an `NpcTalk`; NEAR: the player within `distance`, re-armed beyond `distance + 1`; ROUTINE: whenever nothing else runs, looping, cut by talks and barks and resumed at its step) plays the first available one (`needs` story flags, `once`). An interaction is `NpcStep`s (`kind`: SAY, ANIM, FACE, LOOK, MOVE, SOUND, WAIT, FLAG, LEAVE) run back to back until one waits; locked talks puppet the player and interact advances them. Marks are the NPC's `Marker3D` children (floor points, cached before it moves; children of an instance's internal nodes wouldn't be saved). Walks steer around the player and other NPCs (`_steer`, a detour point beside the nearest one ahead) and wait beside a mark the player stands on (`waiting`), except that an NPC whose own talk holds the player stops beside it; the timeout snap never lands on the player. A MOVE with `lines` first checks the player isn't within `room` of its way, else says one and ends the interaction uncounted. Memory in `World.npcs`: plays per interaction, `gone` (LEAVE: fade, absent, flag), position (restored on load). `appears_if` flags gate presence (a character's copy elsewhere). Presentation reads `anim`, `face`, `look_target`, `speaking` and `cue(name)`; `_animate()` is a placeholder. Resources are `@tool` with `resource_name` summaries and per-kind inspector fields. **NPC Tools** (`addons/npc_tools`): toolbar menu New NPC / New NPC Type (writes an inherited `npc/<name>/<name>.tscn`) / NPCs (N), and while an NPC is selected Add Interaction (templates) and Add Mark (click places a Marker3D child); scene changes are undoable (New NPC Type writes a file). Demo: `demo/npcs/npcs.tscn` (keys 7 reset story, 8 reload).

**Switch puzzles (`puzzle/`, guide in `docs/switches.md`)**: a `Door` (`puzzle/door.gd`, a `MovingPlatform` reused as a shaped body) slides open while every switch on its `channel` is on (`World.openness`). Switches: `WeightPlate` (a `Zone`; HOLD, or LATCH: springs back until every switch on the channel is on at once, then all its latch plates lock), pressed by the player, enemies, NPCs and weights whose gravity points into its face; `EnergySwitch` (charged by `Projectile` through `shot()`, in aim assist via group `aim_target`): each shot adds `time_to_close` up to `× max_shots`, the door follows the energy left. State lives in `World.switches` by `Channels.id`; a door counts its channel's switches from `world/switch_registry.tres` (every saved scene, baked by Platform Tools) plus the loaded ones, so a switch in an unvisited area counts as off. A channel of only locked latch plates is solved (`World.solved`). Weights are `WeightBody` (`puzzle/box.tscn`, `ball.tscn`): `RigidBody3D` with sticky `gravity_dir` and `weight`; characters push them by walking into them (`WeightBody.push_from` after `move_and_slide`); the player carries them (R: `lift` / `put_down`, T: `throw_held`; `Player.held`, stamina drain, drops on hurt). A `Dispenser` keeps `count` weights in play and stops once its channel is solved. `GameArea` writes every weight's state into `World.bodies` each physics frame (keyed by `Channels.placement_id`) and restores it on load; plates wait `WARMUP` frames before reading. Demo: `demo/switches/` (two linked areas). `WeightBody` must not reference the `World` autoload.

**Areas (`world/area.gd`, `GameArea`)**: root script of each playable scene. It expects children `Player`, `Camera`, `HUD/Label` and optionally `Bays` (debug warp targets, each with an optional `Start` marker). It runs the iso camera follow, the debug HUD (`Player.debug_text()` + `World.debug_text()`), debug keys and bay warps (`[ ]`, Backspace), the out-of-bounds fall death (weights out of bounds are destroyed), and weight memory. Each scene subclasses it (`demo/demo.gd`, `demo/puzzles/puzzles.gd`). `SceneDoor` sets `World.spawn` and changes scene; platforms_a and platforms_b link to each other this way.

## Conventions

- `ponytail:` comments mark deliberate shortcuts with a known ceiling (e.g. unrotated zones only, no cutscene timeout). Read them before extending that code.
- Each script has a committed `.uid` sidecar; keep it with the script when moving or renaming (do moves in the editor, or `git mv` both files).
- Static typing and `##` doc comments are used throughout; input actions are defined in `project.godot`.
- In `@tool` scripts create child nodes in `_ready`, not as member defaults (`var _x := Node.new()`): a script reload in the editor re-runs member defaults and leaks those nodes.
